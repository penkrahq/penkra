# Live Claude account switch check (Penkra Dev 2)

Run this only inside a controller Agent Thread in **Penkra Dev 2**, with the 0.14.3 candidate build and two distinct Claude subscription Connections already signed in. This creates one disposable Thread and sends one paid resume probe. Keep the returned Thread and turn IDs; never target the controller Thread. Do not run these commands in a production Penkra window.

## Operator setup

1. Open **Penkra Dev 2** with the candidate build. Sign in two different Claude accounts as Connections in this isolated slot.
2. Start a controller Agent Thread there using either account. Paste the **Agent script** below into that Thread. No account credentials need to be pasted into the prompt.

## Agent script

You are running a bounded live QA check in Penkra Dev 2. Use Penkra's registered commands, one at a time. Do not use another Penkra instance or access its data. Report exact IDs, delivery states, and any errors. Stop if you cannot confirm two distinct authenticated Claude accounts or a runnable model on each.

1. Call `penkra context` and require thread-create permission, then `penkra connections list --provider claudeAgent`. Pick two healthy, signed-in subscription Connections that the operator identifies as different Claude accounts and call their exact IDs `A` and `B`. The listing exposes labels and safe identity metadata, but may not prove account identity by itself; ask the operator to identify the two labels if ambiguous. Do not print credentials. The controller Thread must be different from the Thread created below.
2. Call `penkra models list --availability available --provider claudeAgent --connection-id <A>` and the same command for `<B>`. Choose a model available on **both** accounts, preferring Sonnet if offered; stop if there is no common model. Record whether B offers Haiku, Sonnet, or only that selected Thread model. Use the exact returned model slug and options.
3. Choose a unique run ID (for example the current UTC minute). Call `penkra threads create --input '{"requestId":"qa-claude-account-switch-0143-<run-id>","title":"QA Claude account switch A to B","prompt":"Live QA only. First state the canary ACCOUNT-SWITCH-0143 in one short sentence. Then run a shell command that sleeps for 90 seconds. After it finishes, state DONE. Do not end the turn before the sleep finishes.","target":{"provider":"claudeAgent","model":"<common-model-slug>"},"connectionId":"<A>"}'`. Replace placeholders with exact values; include model options returned by discovery if required. Keep its `threadId` as `T` and first `turnId` as `U1`. If retrying after an uncertain create response, reuse the identical request ID and input.
4. Call `penkra threads read --thread-id <T> --turn-id <U1>` until U1 is **running**. Confirm it has begun the canary/sleep work. If it completes before the next command, stop and report an inconclusive timing attempt; do not claim a steering pass.
5. While U1 is running, call `penkra threads send --input '{"threadId":"<T>","message":"Live QA switch message. Reply with the canary from the earlier turn, then stop.","now":true,"connectionId":"<B>"}'`. Keep `messageId` and `turnId` as `M2` and `U2`. Expect `delivery: "interrupted"` for the running account switch. If routing says `started` or `queued`, report the observed state as an inconclusive running-turn check.
6. Call `penkra threads read --thread-id <T> --turn-id <U2>` until U2 is terminal. Confirm M2 is delivered exactly once and U2 completes without the different-Claude-account guard. Read U1 as well: its partial canary output should remain visible, and U1 should be interrupted. Check the Thread's Connection in the UI or through the available Thread read/diagnostic command; it should now be B. If diagnostics capability is available, call `penkra diagnostics threads activity --thread-id <T> --include-details true` and record the verification result and any reconstruction notice. Do not inspect another profile's data.
7. Report PASS only when U1 was running at send time, the account switch interrupted it, M2 was delivered once, U2 completed, and the Thread binding is B. Report FAIL with the exact error otherwise. State whether diagnostics showed exact native resume or reconstructed context; if that evidence is unavailable, mark continuity **unverified**. Leave the disposable Thread in the isolated Dev slot for review.

This check exercises an A-to-B running-turn switch. The automated tests cover crash recovery, model preference and fallback, and migration behavior. A separate release-integration test must apply diagnostics migration 171 before switch migration 172.
