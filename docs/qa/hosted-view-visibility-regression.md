# Hosted-view visibility regression: runtime investigation

Measured 2026-10-14. Findings only; no product changes. This extends [tab activation, item (h)](tab-activation-hang.md). Evidence and executable scratch harnesses are in [hosted-view-visibility-regression/](hosted-view-visibility-regression/).

**The first bad commit for removing live hosted views from the shell on a window-visibility change is `d752139131f59082991a6c56d70845689fb3fd3b` (2026-09-26, “Fix detached tab command delivery”).** Its immediate parent `a60fdf71f4bca8df93f9df5b52fcc21729040d3d` preserves them. Both were executed, alongside the September fix and current source. Pure loss of application focus did **not** reproduce removal. Moving between two native full-screen Spaces did reproduce it.

The operator's observations contain three distinct changes: physical removal from the shell (September 26); a logical tab-visible flag and replica presentation that already existed at the earlier fix; and the agent-facing `window-hidden` classification introduced October 11. These should not be assigned a single introduction date.

## Runtime before/after and bisect

Each run used the revision's real `AppTabViewHost`, real React `AppDockPane`, and its window hide/show/minimize/restore handlers. The local Browser fixture contains a toolbar and live counter page. The controlled experiment calls exactly `setWindowVisibility(owner, false)` while the native shell itself remains visible, then restores `true`. This isolates host policy from OS event delivery; it does not claim an OS hide occurred in this experiment.

| Executed revision                                              | Before false signal                | After false signal                                 | Restore true       |
| -------------------------------------------------------------- | ---------------------------------- | -------------------------------------------------- | ------------------ |
| `24110c887032cdc78dfad2c74e7e5b32b5b06a7f`, earlier fix        | Live, owner 1, two native children | Owner 1, both native children attached and visible | Live, two children |
| `a60fdf71f4bca8df93f9df5b52fcc21729040d3d`, immediate parent   | Same                               | Same preservation                                  | Same               |
| `d752139131f59082991a6c56d70845689fb3fd3b`                     | Same                               | Owner null, zero native children in shell          | Same               |
| `8327fa1bcf82008acf3c66829cf91b5416669d4f`, tested HEAD source | Same                               | Owner null, zero native children in shell          | Same               |

In **all four**, the false signal sets `AppTabViewHost.isVisible(tab)` false, publishes a replica presentation and causes replica DOM to exist. In the good revisions, the live native views remain above that DOM. In the bad revisions, removal exposes the replica. Detached web contents remain alive; this is not evidence that the renderer is destroyed. Replica presentation may retain an owner identifier even when the host's actual owner is null. See [controlled-summary.json](hosted-view-visibility-regression/controlled-summary.json), per-revision results/screenshots, and [source hashes](hosted-view-visibility-regression/product-source-hashes.json).

A separate scratch git clone recorded the runtime-verified adjacent good/bad boundary using `git bisect --no-checkout`: [bisect log](hosted-view-visibility-regression/bisect.log), [result](hosted-view-visibility-regression/bisect-result.txt). This is an adjacent-pair bisect, not a broad historical runtime sweep. Git history identifies the same first replacement of the preservation branch; no earlier change between the fix and this parent changed that branch.

The historical changed revision also detached on a validated full-screen Space switch; the parent preserved native shell ownership/children off screen. The final HEAD repeat failed to bring the first Space to the foreground before its requested switch, so its Space labels are not treated as a transition reproduction. The initial HEAD run above passed on-screen/document/full-screen preconditions. The parent's Hide baseline was contaminated by an earlier hide and is excluded from the causal comparison. Physical trackpad swiping and a physical Cmd-H keystroke were **not** injected: Accessibility/post-event access is disabled. The measured Space change is macOS switching to an existing native full-screen window through focus; the measured Hide is Electron's native application hide path. Actual operator gesture delivery and a full installed Penkra Dev session remain unverified. No claim that every focus loss emits hide is supported.

## Exact reproduction

1. In a scratch shell with the local Browser fixture selected in the right-side `AppDockPane`, verify owner equals the shell renderer ID, two native child views are attached, and tab presentation is live. Record native/document/tab visibility separately.
2. For the deterministic historical comparison, call the revision's real `setWindowVisibility(owner, false)` once; wait for `window-hide-applied`. Read owner and native child count, and capture the renderer replica. Restore `true`. Parent/fix retain children; introducing/current revisions remove them. This controlled step proves policy, not OS event semantics.
3. For the native Space reproduction, put the first shell full-screen, switch to the desktop to create a second shell, and put that shell full-screen in its own Space. Focus the existing first shell; validate on-screen membership/document visibility, then focus the existing second shell. Log native hide/show, V/M, document visibility, owner and children. Current source receives hide with V/M true/false and detaches.
4. Separately activate the outside-frame scratch Cocoa app to test focus-only loss; minimize/restore the first shell; call native `app.hide()` and log any spontaneous show before declaring it stably hidden.

For an operator-driven scratch Dev reproduction, use the same two full-screen-window setup and swipe between Spaces, then separately Cmd-H, minimize, and click another app without moving Spaces. Those physical actions are a follow-up procedure, not measurements made here.

The executable per-revision harnesses and reconstruction notes are in [README](hosted-view-visibility-regression/README.md). All sources were archived outside the release worktree and linked to existing dependencies; only QA files are committed. Scratch PENKRA_HOME and provider-free local fixtures were used, ports 3919/5919 were explicit, and VITE_DEV_SERVER_URL was set on the Electron process. No production database, installed Production app, real provider account, or paid model call was accessed. All owned scratch processes/servers were stopped.

Scope: this is real historical host/renderer execution inside a standalone diagnostic Electron shell, with installation/session/RPC readiness stubbed. It is not a complete Penkra application startup, nor a measurement of all multiwindow ownership transfers.
