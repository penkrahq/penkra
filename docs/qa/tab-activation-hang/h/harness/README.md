# Full-screen Space and coverage harness

Source a0a576730, version 0.14.4. Reuse the isolated archive/dependency/renderer preparation described in ../../additions/harness/README.md. Never launch an installed app or use Production state. Native shells use the unchanged SingleChatSurface/RightDock renderer with local services/chat fixtures. The Browser d1 toolbar is a placeholder; d2 is the instrumented local probe. Only the first shell owns the hosted page and real host hide/show callbacks. The second shell uses the same real renderer and supplies a separate native full-screen Space or covering window.

Use a fresh QA_ROOT with qa-home/evidence directories and explicit ports 3919/5919. Start the same scratch Vite config. No provider calls or SQLite database. Source paths in the retained main entries expect to run from an archive root with these files copied to qa/ and the renderer/preloads/build dependencies from the previous harness.

For Spaces: start spaces-helper.js through osascript -l JavaScript with QA_ROOT set; build main-spaces.ts via QA_ENTRY and build.mjs; run the archive's Electron executable with QA_ROOT, scratch PENKRA_HOME, explicit PENKRA_PORT and VITE_DEV_SERVER_URL. The helper's desktop window allows a native return to the desktop to create the second full-screen Space. The main entry waits for native full-screen state/events, then focuses the existing windows to switch between their Spaces. It performs three click/type/scroll trials through the authenticated command gateway while the first remains off screen. The scratch observer must have the guard-bypass patch from ../../additions/matrix/guard-bypass.patch; main-spaces.ts turns its flag on. No synthetic keyboard/mouse event is used to switch Spaces.

The original successful Space run used cg-window-list-spaces-legacy.py at qa/cg-window-list.py. Its field named zIndex is only an ordinal from the **unordered** all-windows API; ignore it as a stacking claim. Presence/absence of kCGWindowIsOnscreen and the window's identity/bounds are valid evidence. The updated cg-window-list.py additionally queries OnScreenOnly and exports onScreenZIndex for front-to-back comparisons. Use this corrected helper for coverage checks. It emits metadata only for the own scratch PIDs; no screen image or unrelated application content is captured.

The first coverage entry main-cover.ts performs an uncovered control and same-app partial/full covers, then another-app attempts. An activating helper can switch Spaces, invalidating “only covered”; those attempted rows must not be treated as valid covers. The passive separate-app control uses main-cover-other.ts and cover-helper-passive.js. It raises an opaque floating window without activating its application, preventing activation-driven Space switching. Its layer/collection behavior and exact WindowServer ordering/bounds are part of the measured configuration. A prior helper-control quit file must be removed before starting a fresh helper process.

Every run writes the same filenames; move evidence into separate directories before another run. Raw observations include all phases; use the action markers, geometry validation and accepted-case summary, rather than attributing reset/cleanup events to coverage. First setup failures are retained under excluded/ and are not product verdicts. The native fullscreen request timed out in two early setups; the successful setup verifies state and retries the diagnostic request when necessary. Early coverage attempts also had foreground/Space movement or lacked an ordered stacking check.

Close only the own scratch windows/processes after the run. Native fullscreen/Space transitions temporarily change foreground UI; no OS setting, signing, installation, product source, provider account or paid call is needed. Source copies and diagnostic scripts are evidence, not proposed product fixes.
