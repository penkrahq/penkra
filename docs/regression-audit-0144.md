# Rebuild regression audit: transcript and existing-thread selection

Code-read comparison: `v0.14.3` versus `5897d4141`, 2026-10-13. Report only; no fixes, provider restarts, installation, or Production database access. Runtime outcomes below are **source-path conclusions**, not a new end-to-end provider test. The existing Chore native reproduction is documented separately. The withdrawn OpenCode and selection-notice designs are not implemented.

## Transcript elements

“Historical activity omitted” means an ordinary `projection_thread_activities` row with no matching `notices` record. Migration 176 separately imports tool operations/activities, all non-approval `notices`, and user-input pending interactions. Therefore the remaining-activity allowlist alone cannot establish loss of an equivalent independently stored notice/tool/question. Migration 201 later deletes the old tables, so an omitted ordinary activity cannot be restored by the current renderer.

### Isolated migration evidence

An ephemeral in-memory Vitest probe ran migrations through 175, seeded one normal activity for each of 13 kinds, then ran 176. It asserted the retained set exactly: `provider.turn.start.failed`, `runtime.warning`, `context-compaction`, `media.presented`, `runtime.error`. The omitted set: created-thread, reconciled, connection/model, task.started, turn.aborted, requested/resolved question activity. (Reasoning is the sixth allowlisted kind, not seeded in this probe.) One probe passed in 2.20 seconds; log `/tmp/penkra-regression-audit-migration.log`. The temporary probe source was removed. This used no Production database. Existing migration-176 code separately shows pending-question and non-approval-notice import.

### Capability conclusion

All three adapters still declare `sessionModelSwitch: 'in-session'` (Codex :2146, Claude :5634, OpenCode :4241). There are no runtime consumers outside declaration/type after Reactor deletion. This does **not** establish harmlessness: coordinator explicitly restarts changed model ids, and Claude's spawn-fixed max-effort safeguard was lost while its live setter still assumes that safeguard exists. The adapters' per-turn model wire fields remain; policy ownership and restart behavior changed.

### Remaining uncertainty

This report does not claim an exhaustive UI/native execution proof. It inventories old producer cases, retained web consumers, migration paths and current request wiring. Exact upstream model/effort acceptance, whether an operator saw cross-provider switching through another historical route, workflow-specific task-panel losses, the no-item compaction path and per-provider tool-progress-only output require isolated targeted reproductions if the operator wants implementation designs. No fixes are chosen here.
