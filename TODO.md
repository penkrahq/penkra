## 2. Rules the built design must keep true

These are built. Step C and later must not reintroduce anything they forbid; the final checks (F, G, 6) verify them.

### 2.1 Data model
- Kept tables, unchanged and not renamed: `projection_spaces`, `projection_folders` (+ `app_tabs`, 2.12), `space_navigation_state`, `auth_sessions`, `auth_pairing_links`, `provider_connections`, `provider_credential_profiles`, `provider_installations`, `managed_attachment_blobs`, `managed_attachment_cleanup_jobs`, `connection_usage_daily`, `connection_usage_turn_events`, `retention_active_days` (2.20), `effect_sql_migrations`.
- `threads` columns: `id` (client UUID), `space_id`, `folder_id NOT NULL REFERENCES projection_folders`, `title`, `provider`, `connection_id` (NULL = anonymous route; always the account that owns `native_state_id`/`provider_session_id`, 2.4), `model`, `model_options`, `runtime_mode`, `provider_session_id`, `native_state_id`, `state` (idle | running | error), `active_turn_id`, `last_error`, `draft`, `draft_updated_at`, `queue`, `created_by`, `created_by_thread_id`, `sidebar_sort_order`, `last_activity_at`, `last_message_preview`, `last_user_message_at`, `last_visited_at`, `open_question_count`, `archived_at`, `deleted_at`, `created_at`, `updated_at`. No parent thread, deck, working directory, pin or owner column.
- `thread_items (thread_id, seq, source_id, turn_id, kind, status, text, data, created_at, updated_at)`, PK `(thread_id, seq)`, UNIQUE `(thread_id, source_id)`, FTS `thread_items_search`. Statuses: user `sent|failed`; text/reasoning `streaming|done|interrupted`; tool `running|done|error|interrupted`; question `open|answered|cancelled`; notice `done`. Nothing else is written.
- Sidebar status is derived in the read: running → attention (open questions or `state='error'`) → done (`last_activity_at > last_visited_at`) → idle.
- One item write (upsert on `(thread_id, source_id)`, `seq` assigned on first insert) that updates the thread summary columns in the same transaction. `data` ≤ 64 KB, one copy, `"truncated": true` + original length when cut. Pages of 50 by `seq`; no query scans items across threads.

### 2.2 No receipts, no journal
- Create = client UUID + `ON CONFLICT DO NOTHING`. Set state = plain `UPDATE` to the target value. Each operation validates, writes in one transaction, publishes. One in-memory publisher per thread; nothing persisted for the stream.

### 2.3 Turn state
- One consumer per thread: `turn started` → running; item events → upsert; `turn ended` → idle (or error with `last_error`), settling running/streaming items to `interrupted` in the same write.
- Cut-offs only: provider process exit, Penkra start → idle, items interrupted, one notice "This turn was cut off because the provider stopped." No automatic resume. A turn that fails to start never becomes running and inserts no user item. `error` blocks nothing. Archive allowed unless running. Stop shows "Stopping…" until the end event or exit. No turns table.

### 2.4 Sending, queue, steer, interrupt
- `threads.queue`: `{ messageId, text, attachments, senderThreadId, dispatchOrigin, queuedAt }`, oldest first, mirrored in memory. An entry stores no provider, model or connection; delivery uses the draft's selection at that moment, else the thread's current values.
- Composer pick (operator, 2026-10-11): picking provider/account/model writes only the draft selection in `threads.draft`. `connection_id`, `model`, `native_state_id` change only when a turn starts on the new selection; a different account of the same provider goes through the 4.1 switch. Applies to every provider. A running turn keeps the account and model it started on.
- Plain send: deliver if not running and the queue is empty, else append. Turn end delivers the head. A head that fails to start stays at the head, the thread goes to `error`, and nothing more is delivered until the next send (which retries the head) or the user removes/edits it.
- `now`: Codex/Claude native steer; OpenCode, or a different account selected: interrupt, then deliver as the next turn ahead of the queue. Nothing running → plain send. Delivery inserts the `user` item `sent` at that moment.
- Send results, returned on the event, no timer: `started` (`turnId`), `steered` (`turnId`), `interrupted` (`turnId`), `queued` (`position`, `queueLength`, `runningTurnId`), `failed` (`error`, unchanged provider text). All return `threadId`, `messageId`.
- `penkra threads interrupt`: `--thread-id` interrupts the running turn; `--message-id` removes a queued message. No `--turn-id`.
- Edit a queued message only with an empty composer (moves it to the draft in one write); otherwise the toast "Clear or send your message before editing a queued one." and nothing changes; the server enforces the same rule.
- Removed and must not return: editing sent messages, pinned messages, thread notes, sidebar pinning, `/fork`.

### 2.5 Questions, approvals, subagents
- Questions are `question` items (open → answered/cancelled). Approvals removed entirely. Subagents disabled: Claude `disallowedTools: ["Task","Agent"]`, OpenCode `tools: { task: false }`, Codex `features.multi_agent=false`.

### 2.6 Composer draft
- One draft per thread in `threads.draft` (text, attachments, pasted text, comments, mentions, skills, selections, terminal contexts, model and account selection, runtime mode). Written 300 ms after the last keystroke; later `draft_updated_at` wins; broadcast to other windows. Sending clears it in the same write. No localStorage drafts. A "+" draft tab exists only in window memory until its first send (2.19 C).

### 2.7–2.10
- Attachments: files on disk, providers get paths. OpenCode keeps image parts only in the newest user message (`[image: <path>]` elsewhere).
- One SQLite connection; every query bounded, timed and under 50 ms on a Production copy; fix slow queries at the cause.
- The app never refuses to start: a failed migration rolls back and shows "Penkra could not upgrade your data: <error>. Your data is unchanged; contact support.", read-only from the old tables. Plain logs in `userdata/logs/{server,desktop}.log`, rotated at start above 50 MB. No diagnostics machinery or `diagnostics.sqlite`. `DatabaseLifecycleLock` stays.
- Credentials are read only when a provider process launches; the credential pipe has no timer.

### 2.11 Agent-facing text (item H)
- Scope: the `penkra` MCP host prompt, `penkra --help`, every operation's `--help`, `SERVER.md`. Every statement true for the code as built; every result says what it means and what the caller does next; nothing said twice; no mention of approvals, subagents, diagnostics, interrupt turn ids, receipts, decks or pins.

### 2.12–2.13 App tabs and tool results
- Only the tab list is shared, in `projection_folders.app_tabs` (one write + broadcast per change); selection, panel visibility and dock width stay per window in memory.
- No `--tab-id` → always a new tab; `--tab-id` → that tab or `TAB_NOT_FOUND`. Window choice: home window if showing the folder and the person is not busy in its right panel, else the first such window in focus order, else open in the background (`visible: false`) and activation/screenshot fail with `TAB_FOLDER_NOT_AVAILABLE`. No timer.
- Results up to `INLINE_TOOL_RESULT_BYTES` inline, larger ones to `userdata/tool-results/<threadId>/<opId>.txt` as `{ resultFile, bytes }`. `tabs list` returns only `tabId, appId, appName, title, status, visible`, plus `url` for web pages. No `tabs diff`; screenshot has no `document` option; the agent cursor shows only agent input.

### 2.14–2.19 Navigation
- Sidebar search runs on the server (`searchThreads`), never in the browser. The shell comes only from the startup bootstrap (spaces, folders, running threads) and the live stream; no fallback re-reads; other thread rows come from paged lists and `getThread`.
- A folder is the tab set; every thread has exactly one folder and runs in the folder's `workspace_root`, else its scratch directory. Folders can set and clear a directory. Settings "Archive" lists archived Spaces, Folders and chats with Restore only.

### 2.20 Retention
- Auto-archive after 7 active days without activity (not running, no open question); delete any archived chat after 30 active days from `archived_at`. Constants in one module; no marker of who archived.

### 2.21 Explorer 0.2.14
- Path-based `resources.open`; no host handles, no `setTimeout`, no polling; `explorer.watch` resolves on change and rejects on abort or watcher error. Typeahead has no timer (clears on click, blur, non-printable key).
